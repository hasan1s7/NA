# Nabu 1.5.0 - expanded bank and feature previews

Date: 2026-11-05. Source: the accessible attached `nabu-next-release-overnight.zip` (1.4.1). Its existence was checked before extraction. Work was performed in a separate directory. The old handoff and report are retained under `docs/history/1.4.1-*`.

## Delivered in this release

- Tripled each component, not just the combined count: **900 word meanings, 90 practical phrases, 36 source-language expressions**. Previously 300 / 30 / 12. Total **1,026 concepts**, **12,312 language forms**, **135,432 directed sense-aligned translation links**, **132 language pairs**. Twelve supported languages remain English, Spanish, French, Arabic, simplified Chinese, Russian, German, Italian, Japanese, Korean, Portuguese and Turkish.
- Added 600 genuinely distinct word records across 24 new topics, each containing 25 entries; preserved all 342 original concept IDs, senses and spellings. Word homographs (animal/computer mouse, noun/verb sleep, fly insect/verb) remain separate senses. No learner data is prefilled or rewritten.
- Added 60 phrases and 24 expressions. There are now three expressions supplied in each source language. All added phrases/expressions include usage, twelve-language examples and possible replies, and explicit unverified-draft provenance. Source expressions have literal renderings in the other eleven languages; ordinary phrases have explicitly English wording glosses, not falsely labeled literal target translations. The expression source language is not a claim about historical origin.
- Added All / Words / Phrases / Expressions filters, topic filtering, accurate counts, and 60-row incremental rendering. Search is no longer capped at 1,000 records. Search indexing includes all spellings, aliases, senses and literal images, but fuzzy search does NOT silently become an exact translation.
- Exact lookup now tolerates surrounding Unicode punctuation including Spanish inverted question/exclamation marks. Distinct accents and Turkish casing remain significant under the existing rules.
- Bank detail now exposes Learn this, rich details, and the same truthful device/pending/synced status as the translator. Ordinary-phrase English glosses are visible in the collapsed-detail area after opening it; optional target-language localization remains an explicit provider action.
- Added reproducible authored expansion inputs and merger, manifest, legacy-ID compatibility assertions, 12 new JS regression cases and 19 new integrated UI checks. Updated release/build identifiers and SHA-256 CSP hashes.
- Captured twelve feature screenshots from the actual bundled app running with an actual isolated API and SQLite database. The screenshot harness explicitly replaces URL/history, browser IndexedDB and fetch/cookie transport boundaries. The accounts and paragraphs are fictional test data. No preview is a design mockup or hosted validation claim.

## Build / inspect

```sh
npm run build
npm test
python -m pytest -q
npm run test:ui
```

`npm run build` runs `tools/expand_bank.py`, `tools/build_graph.py`, then `tools/build_standalone.py`. The expansion merger is idempotent. Edit `data/expansion/words.tsv`, `phrases.json`, `expressions.json`, `replies.json`, `expression-examples.json` and `corrections.json`, then rebuild. Canonical output is in `data/wordgraph-source.json` and `data/phrasebank-source.json`; `public/index.html` is the generated self-contained app.

The release is byte-for-byte reproducible for canonical data and generated app on this runtime. See `verification/expansion/reproducible-build.json`. Tested with Python 3.13 and Node 22; existing project requirements apply. Browser fixture runners use `/usr/bin/chromium`; adjust the test executable path to a local Chromium installation when necessary.

## Compatibility and deployment

This is the whole backend app, not a three-file Pages patch. Server DB schema remains v3; IndexedDB name/version and the existing scheduler are unchanged. Back up a deployed database using a consistent online backup, export any guest library, deploy the whole application to a controlled staging host, and retain the existing private database volume. **Do not replace, erase or import over a live database.** No new credentials, paid services or database migrations are required for the bank itself.

After deployment, confirm the Word bank filters read 900 / 90 / 36. Confirm the correct service-worker build (`nabu-bank-20261105-r3`). If the old UI persists, use the existing repair page without clearing site data. Account hosting still requires the existing backend and persistent private storage. The built-in bank itself works without translation keys; text outside it still needs a configured provider or manual entry. Speech remains the existing optional service, not a recorded-human pronunciation library.

## Outstanding gates preserved from 1.4.1

- Native HTTPS cookies, actual IndexedDB durability, service-worker offline reload, multi-device persistence, Web Locks and browser shutdown/restart still need real staging-browser testing. Native navigation was blocked by the execution environment; fixture tests are not a substitute.
- Actual encrypted off-server backup upload/download/restore drill and monitoring against a privately configured bucket remain unverified. Existing simulated backup tests passed. Never use the live DB as a restore target.
- Password recovery remains a one-use saved recovery code, not email. Losing both password and code still prevents self-service recovery.
- The production scheduler remains explicitly SM-2-inspired; the optional read-only FSRS evaluation is unchanged and not newly installed or validated here.
- Language quality is unverified AI-assisted authored draft content. Complete a native-speaker pass, especially gender, kinship branches, register, regional variants, glosses, idiom senses and example pragmatics. Consult `docs/BANK_CONTENT_REVIEW.md`. Tests check structure and behavior, not pedagogy or native-level accuracy.
- Existing single-instance SQLite scaling, privacy/deletion, receipt retention, backup limits and provider configuration gates remain. Shared snapshots still have the intentional 300-card limit; split large libraries into collections.

No repo was pushed, host created, service purchased, provider called, user emailed, secret exposed, or production database opened. The source archive excludes database files, private configuration and caches. Preview-account credentials and recovery codes are not shipped as a database or shown in screenshots.
